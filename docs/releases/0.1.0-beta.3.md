# DroidPier 0.1.0-beta.3

**Experimental Linux x86-64 and Android preview.** This is not a stable release or
a claim of universal device/distribution support. Windows and macOS remain in
development. Beta.1 and beta.2 downloads are unchanged.

## Changes

- **The desktop is rebuilt against its design reference, surface by surface.**
  Boot, desk, taskbar, launcher, command palette, shortcut sheet, window switcher,
  window chrome, diagnostics, settings, connection and permission screens were
  compared against the running reference implementation, page by page and
  interaction by interaction, and brought to it. Bundled fonts, a single token
  system for colour, radius, spacing and duration, and light/dark parity throughout.
- **The phone's own screen appears on the desk.** *Phone Mirror* streams display 0
  into the phone-shaped frame, view only: it follows the phone when it rotates and
  states plainly what it is doing when it has no picture — connecting, or the
  reason it stopped, with a retry.
- **Searching from the desk opens on the phone.** The phone is asked which app
  handles the address and that browser opens on a fresh display with it, streamed
  as another window, instead of the browser on the computer.
- **Four desks that do something.** *Move to desk n* in a window's title-bar menu,
  `Ctrl + Alt + Left/Right` to step between them, and the desk names the one you
  land on for a moment.
- **App icons are the app's own artwork.** The agent reads each application's icon
  resource before the launcher-themed drawable, so phones that hand out pre-cut
  circular icons no longer flatten every tile into a plain disc.
- **Everything that opens, opens.** The launcher, the modals, the control centre,
  the notification centre, the mirror and the companion view fade and rise into
  place. Closing stays instant, so a dismissal never lags the key that asked for it.
- Launcher rows list application names rather than package names; system
  applications keep a small *System* tag. The tray clock is a readout again and the
  status cluster is the single door to the control centre. Settings fill their
  card, the companion view is its own phone frame naming the linked computer and
  the link's age, and one icon scale replaces the nine sizes that had accumulated.

## Performance and known limitations

**60 FPS is not restored.** The direct pipeline's measurements are unchanged from
beta.2: about 39–47 displayed frames per second on the tested Redmi Note 7 Pro /
Intel UHD 620 pair. These remain development measurements, not guarantees.

**The phone-screen view is view-only.** It shows what the phone is showing; taps
and keys go to the application windows instead. It shares the phone's video
encoder with those windows, so a phone already streaming several windows may have
little encoder capacity left for it.

**Searching on the phone needs a browser the application list carries.** A phone
with no handler for web addresses is told to the user rather than quietly falling
back to the computer's browser.

Audio is not forwarded to the computer; media controls do not provide audio
playback. Restricted/DRM applications and applications rejecting secondary
displays may not work. Physical manual-code/QR pairing and the full Linux and
device matrix remain unverified.

## Installation and upgrades

Download the APK or the appropriate DEB, RPM, AppImage or portable archive from
this release. Packages contain the identical signed companion APK and agent; no
Flutter, Java, Android SDK or compiler is needed on the user's computer.

Verify the file against this release's `SHA256SUMS` before installing:

```sh
sha256sum --ignore-missing -c SHA256SUMS
```

Quit the previous desktop before starting beta.3. Install the new desktop package
using the [user guide](../USER_GUIDE.md). Its bundled companion upgrades the
official beta.2 APK in place using the same signing certificate and versionCode 3.
Do not uninstall the signed companion for a normal upgrade. A debug-signed
companion cannot be replaced in place; migration is an explicit user decision that
loses that application's data. DroidPier never performs that uninstall
automatically.

Keep Play Protect enabled and use its scan flow. Signing establishes update
identity, not a Google approval or a guarantee that sideloading has no warnings.
Notification forwarding and clipboard sharing remain optional.

## Verification and provenance

See the version-specific [acceptance record](../../release/acceptance.json) for
completed checks and explicitly pending coverage. Automated tests do not replace
physical Wi-Fi or full distribution acceptance.

Every change in this version entered `main` through a pull request whose required
`source-and-linux` check passed, and the merged result was re-verified as a whole:
analysis clean and all tests passing across the desktop application, the shared
API and core packages, and the platform plugin.

Three parts of this version were exercised against a physical Redmi Note 7 Pro on
Android 13 rather than against test doubles, because a fake accepts any command a
caller invents. The screen mirror streamed display 0 and stopped cleanly. Opening
a web address resolved the phone's browser, started it on a fresh display and
streamed it, and that check found two faults no unit test could: an `am start`
option Android does not have, and an address truncated at its first `&` by the
phone's shell. The application catalogue returned an icon for every installed
application, as the application's own artwork rather than a themed disc.

The distribution matrix, physical wireless pairing, clipboard, notification,
permission and cleanup acceptance are pending for this version and are recorded as
such. They are not inherited from beta.2.
